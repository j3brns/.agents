# ADR-0019: Docs published as code to GitLab Pages; wiki rejected

- Status: accepted (2026-06-13) · Spec: mkdocs.yml, .gitlab-ci.yml · Decision log: D24

## Context
Operators and developers need a served docs collection — quickstart, stage guide,
runbooks, spec, ADRs. Candidates: GitLab wiki, an external docs platform, or
docs-as-code on GitLab Pages.

## Decision
MkDocs Material built from the existing `docs/` tree (plus README and runbooks copied
in at build), published to **GitLab Pages on every default-branch merge**, with
`--strict` so broken links fail the build. Mermaid renders natively. Latest-only at
launch — the spec carries its own version history (no mike/versioned-site machinery,
per the simplicity contract). The **wiki is rejected**: it diverges from the repo, has
no MR review, and breaks the traceability invariant that downstream docs move with spec
deltas in the same MR (REFINEMENT.md step 4). When the catalog exists, the pages job
becomes a `causeway/docs` component so product repos can publish the same way.

## Consequences
The docs site is regenerated by the same MR that changes the spec — documentation can't
drift from decisions. Cost: docs URL only exists once the repo lands on the GitLab
instance; until then the markdown tree on the branch is the site.
